# Road to Legend

Copero식 **축구 선수 커리어 시뮬레이션**과 **세계 관전 모드**를 합친 웹게임입니다.
빌드 단계 없이 정적 HTML + 순수 JavaScript로 돌아가며, 진행 상황은 브라우저(IndexedDB)에 저장됩니다.

- 배포: https://roadtolegend-beige.vercel.app/
- 현재 버전: **v39** (2026-11-25)

| 규모 (새 세계 기준) | |
|---|---|
| 리그 | 201개 (1~4부, 나라별 실제 승강 구조) |
| 구단 | 3,382개 (실제 2군 16개 포함) |
| 선수 | 약 86,500명 (FC27 실선수 18,137명 + 유스 174명 + 가상 선수, 생성 이름 중복 0) |
| 국내 컵 | 45개 · 대륙 대회 UCL/UEL/UECL/ACL · 국가대표 대회 |
| 실제 임대 | 269건 적용 (2026/27 시즌 초 기준) |

## 1. 주요 기능

**커리어 모드**
- 유스 아카데미 선택 → 1군 데뷔 → 이적·임대·재계약 → 은퇴까지 한 선수의 일생
- 실축 모드(FC27 실선수·실구단) / 가상 모드, 난이도별 성장
- **데이터셋 선택 (v38)**: 새 게임(커리어·실존 선수·관전)마다 `FC27 ver.` / `FC27+TFMKT ver.` — TFMKT는 현재(명단·능력치·계약)는 FC27, 게임 이전 경력·이적·부상·시장가치·구단 역사는 Transfermarkt
- 경기 단위 출전·평점·골·도움, 결정적 순간(N지선다), 이벤트, 시즌 목표, 상점·개인 코치·특성
- 발롱도르(30인)·골든보이·골든슈 시상식, 도전과제, 은퇴 일대기·명예의 전당

**세계(관전) 모드**
- 모든 리그가 실제 일정(유럽식 8~5월 / 캘린더식 2~11월)으로 하루 단위 진행
- 국내 컵 전 라운드, UEFA 리그 페이즈(포트 추첨), 녹아웃, 국가대표 A매치·대회
- 이적시장(여름·겨울) 타임라인: 빅 사이닝, 임대, 자유계약, 2군↔1군 이동, 은퇴
- 조추첨 연출(오픈 추첨, 상·하위 리그 두 포트, UEFA 포트 추첨)
- 세계 뉴스(해트트릭·이변·감독 경질·이적 등), 팔로우(리그·대회·구단·선수·국가대표)

**경기·데이터베이스 화면 (FotMob 스타일)**
- 경기 팝업 탭: 경기(타임라인: 골·VAR 골 취소·카드) / 라인업(포메이션) / 통계(점유율·슈팅맵·xG·선수별 지표) / 순위·대진 / 상대전적
- 선수 경기 상세(하이라이트·히트맵), 선수 프로필(기본 정보·이적 가치 그래프·시즌 지표·커리어·트로피)
- 선수·구단 검색(구단 로고 표시), 구단 스쿼드(1군/2군), 연도별 성적

## 2. 실행과 배포

### 로컬 실행
빌드가 없으므로 아무 정적 서버로 폴더를 열면 됩니다.
`file://`로 직접 열면 IndexedDB·일부 브라우저 정책 때문에 저장이 안 될 수 있으니 서버를 쓰세요.

```bash
python3 -m http.server 8080      # 또는 npm start
# 브라우저에서 http://localhost:8080
```

### 배포 (Vercel / GitHub Pages)
- **Vercel**: 저장소 연결 → Framework Preset `Other`, Build Command 비움, Output Directory `.`(루트).
- **GitHub Pages**: Settings → Pages → Branch `main` / `/ (root)`.
- 캐시 주의: 파일 이름에 해시가 없으므로 배포 후 강력 새로고침(Ctrl+Shift+R)으로 확인합니다.

### GitHub 첫 업로드
```bash
git init
git add .
git commit -m "Road to Legend v30"
git branch -M main
git remote add origin https://github.com/<계정>/road-to-legend.git
git push -u origin main
```
> `data_fc27.js`(약 1.9MB), `logos_pack.js`(약 2.6MB)는 100MB 제한보다 훨씬 작아 Git LFS 없이 올라갑니다.

## 3. 폴더·파일 구조

```
/
├─ index.html          화면 뼈대 + 전체 CSS(인라인) + 스크립트 로드 순서
├─ data_*.js           데이터 (선수·구단·유스·임대·국가·확장 리그)
├─ *.js (엔진)         시뮬레이션 (UI 없음, Node에서도 동작)
├─ ui*.js              화면
├─ logos_pack.js 등    이미지 팩 (WebP base64)
├─ tools/              검증·데이터 생성 도구 (배포에는 불필요)
│  ├─ load.js          Node에서 엔진 불러오기
│  ├─ verify.js        회귀 검사 (N시즌 시뮬레이션)
│  ├─ check.sh         전체 JS 문법 검사
│  └─ data/            유스·임대 데이터 생성 스크립트와 원본
├─ package.json        npm 스크립트 (start / check / verify)
└─ README.md
```

### 스크립트 로드 순서 (index.html)
순서가 곧 의존성입니다. **새 파일은 반드시 이 목록의 알맞은 자리에 추가**하고, `tools/load.js`에도(엔진 파일이면) 같은 순서로 넣어야 합니다.

```
데이터   data_fc27 → data_fa → data_yth → data_loans → data_mgr → data_rank → data_crank → data_legends → data_rivals → data_world → data_names → data_ext → profiles
엔진     core → world → market → cups → season → history → tactics → matchdb → puskas → lrec → rank → crank → legends → tm → matchstats → calendar
         → wnews → events → moments → game → shop → achievements → bio
이미지   logos_pack → flags_pack → logos → extras
화면     ui → ui_pages → ui_world → ui_match → ui_draw → ui_db → ui_mfind → ui_pprof → ui_explore
         → ui_cal → ui_news → ui_cer → ui_wsim → ui_pk → ui_lrec → ui_viz → ui_charts → ui_games → ui_settings → ui_extra
시작     <script>TCUI.boot();</script>
```

> v38: `data_names.js`는 `data_world.js` 바로 뒤, `tm.js`는 `legends.js` 바로 뒤. `data_tm.js`·`data_tmh.js`·`data_tmp0~7.js`는 index.html에 넣지 않는다 (TFMKT 게임에서만 `C.TM.load`가 늦게 불러온다).

### 경기 기록
- `MD.play` / `MD.decode` → `{ ev: [{k, m, s, p, a}], ln }` (k: 이벤트 종류, m: 분, s: 팀 0/1, p: 선수, a: 도움)
- `C.MS.gen(o)` → `{ PL, P, shots, H, tot, POS, vars, key }`
  - `C.MS.keyOf`(경기 내용 기반 키)와 `C.MS.strOf`(FC27 기본 OVR 평균)로 **어느 화면에서 열어도 같은 통계**가 나옵니다. 호출부에서 임의 키를 만들지 마세요.
  - `o.nc = 1`이면 캐시를 건너뜁니다 (검증용).
- `C.MS.team(ms, side, half)` — half 0 전반 / 1 후반 / 2 전체

### 저장소
- IndexedDB: DB `touchline-career`, 스토어 `kv`
  - `save` 현재 게임 (시즌 보관 기록·피로 기록 제외), `ps` 선수 시즌 기록, `mx:<시즌>` 경기 기록, `tx:<시즌>` 이적 기록
  - `chk` + `ch:<대회>` 진행 중 경기 기록 (대회별, 바뀐 대회만 다시 씀), `ark` + `ar:<시즌>` 시즌 보관 기록 (시즌별). 예전 `calh` 형식은 불러올 때 옮긴다
- localStorage: 명예의 전당(HOF)
- 저장 형식이 바뀌면 `S.v`를 올리고 `GM.parse`에서 이전 버전을 변환하세요. 세계 생성 단계(유스·2군·임대 적용)가 바뀐 기능은 **새 세계에서만** 반영됩니다.

## 7. 데이터 갱신 방법

### FC27+TFMKT 데이터셋 (`tools/tm/`)
원본: [salimt/football-datasets](https://github.com/salimt/football-datasets) Transfermarkt 자료 (선수 프로필 2025-10 기준, 경기 기록·이적은 Git LFS 파일, 부상 2026-09-29 갱신).
1. `clubs_tm.py` → `match_clubs.py`(이름·국가) → `club_vote.py`(선수 겹침 투표) → `club_final.py` : 게임 구단 ↔ TM 구단 (`club_final.json`, 높음/보통/낮음). 잘못 이어진 구단은 `build_tm.py`의 `FIX`에서 바로잡는다
2. `match_players.py` : FC27 선수 ↔ TM 선수 (이름+생년월일 일치 → 이름+같은 출생 연도·구단 → 검토 대상). 1~4단계만 쓴다
3. `build_tm.py` → `build_clubs.py` : 경력(2024/25까지, `CUT`)·이적(2025-11 전)·부상(2026-07 전)·가치·A매치·구단 시즌
4. `s2526.py` → `s26map.py` : 2025/26(캘린더 리그 2025) 실제 결과 (순위표·우승·승격·컵·대륙·월드컵·수상·득점왕, 겨울 이적 명단)
5. `build_data.py` → `data_tm.js`·`data_tmh.js`·`data_tmp0~7.js`, `build_names.py` → `data_names.js`
- 2025/26 사이 이동: TM 소속(2025-10)과 FC27 소속(2026-09)이 다르면 이동. 유명 겨울 이적 명단에 있으면 2026년 1월, 아니면 2026-06-20~07-31 임의 날짜. TM 임대 중이던 선수는 2026-06-30 복귀 후 판단, FC27 임대(`F.LOANS`)는 7월 임대
- 레전드: 그 구단 경기 기록(임대 시즌 제외)·리그 우승(그 시즌 10경기 이상, 25경기 이상이면 주역). 배경(X) 구단은 세계 구단 랭킹 자료가 있는 곳만

### 유스 추가 (`data_yth.js`)
**확인된 현재 명단만** 넣습니다 (2026/27 시즌, 2026년 11월 기준: UEFA 유스리그 등록 명단, 구단 U18 명단, 2026/27 임대 목록).
한 줄 형식:
```
이름|포지션|구단ID|국적|yyyy-mm|OVR|POT|주발
```
- 원본 명단은 `tools/data/youth_src.txt` (`#구단ID` 다음 줄부터 `이름|GK/DF/MF/FW|국적|나이`), 변환은 `python3 tools/data/gen_youth.py tools/data/youth_src.txt data_yth.js > new.txt` (출력된 줄로 `data_yth.js`의 명단 블록을 바꿉니다. 예전 기록에 있는 선수는 포지션·출생 월·능력치를 이어받습니다).
- 나이는 명단 기준(출생 연도 확정, 월은 예전 기록이 있으면 그 값, 없으면 추정). OVR·POT는 나이·소속 수준으로 맞춘 추정치입니다.
- FC27에 이미 있는 선수는 이름+출생연도(±1)로 걸러집니다. 구단당 상한 30명.
- 시즌이 바뀌면 명단을 다시 받아 교체하세요 (졸업·이적한 선수가 남지 않도록).

### 2군 추가 (`F.BTEAMS`)
- 실제 3부 이하 리그에 속한 2군만 대상입니다. 구단 ID, 1군 ID, 소속 리그를 넣으면 세계 생성 시 팀이 만들어지고 로스터는 유스 위주로 채워집니다.
- 2군은 국내 컵에서 빠지고, 1군과 같은 리그나 그 위로 승격할 수 없습니다.

### 실제 임대 (`data_loans.js`)
1. 원본 목록을 `tools/data/loans_raw.txt`에 `선수|원소속 구단명|임대처 구단명` 형식으로 넣습니다.
2. `node tools/data/resolve_loans.js` — 구단명을 ID로 바꿉니다 (`ALIAS` 표로 별칭 보정, `STOP` 단어로 일반 단어 오매칭 방지, 점수 0.99 이상만 채택).
3. 결과를 확인해 `data_loans.js`에 반영합니다. 18세 미만은 임대가 적용되지 않습니다.

### FC27 선수 DB (`data_fc27.js`)
자동 생성 파일이므로 직접 고치지 말고 원본 스크립트(`realdb/fc27.py`)로 다시 만드세요. 구단 인덱스가 바뀌면 `data_yth.js`·`data_loans.js`의 구단 ID는 그대로 쓰이지만, 새 구단이 생기면 로고 매칭을 확인해야 합니다.

### 무소속 선수 (`data_fa.js`)
`F.FA`에 실제 무소속 선수를, `F.FA_MOVE`에 시즌 초 이동을 넣습니다. 근거 기사 출처를 주석으로 남깁니다.

## 9. 코드 작성 규칙

- **엔진과 화면 분리**: `core·world·cups·season·calendar·matchdb·matchstats` 등 엔진 파일에서는 `document`/`window` UI 접근 금지.
- **결정적 난수**: 시뮬레이션 진행(경기 결과·이적 등)은 일반 난수를 쓰지만, **나중에 다시 계산해서 보여 주는 값**(경기 세부 통계, 유스 이름·능력치 등)은 반드시 시드 난수 `C.seeded('<접두사>|' + 키)`를 써야 합니다. 그래야 저장/불러오기 후나 다른 화면에서 열어도 값이 바뀌지 않습니다.
- **저장 크기**: 상태 `S`는 IndexedDB에 통째로 저장됩니다. 큰 배열(경기 이벤트 등)은 `mx:`/`tx:` 키로 시즌별 분리 저장하고, 스쿼드 항목은 객체 대신 배열(`e`)을 유지합니다.
- **새 필드 추가 시**: `e[]`에 인덱스를 늘릴 때는 `C.ensureE`에서 기본값을 채우고 이 README의 표를 갱신하세요.
- **CSS**: 모두 `index.html` 안에 있습니다. 새 컴포넌트는 짧은 접두사 클래스(예: `.pf2`, `.mtabs`, `.drpot`)로 묶고, 모바일 미디어쿼리를 같이 작성합니다.
- **문구**: 화면 문구는 한국어. 선수 이름은 원어 표기 유지(검색은 악센트 제거 비교).
- **파일 머리 주석**: 각 파일 첫 줄에 한 줄 설명을 둡니다 (`// Road to Legend — …`).

## 11. 알려진 한계

- 스페인·네덜란드·벨기에 등 **2군 실제 명단**은 공개 데이터가 부족해 일부가 생성 선수입니다.
- **실제 임대 데이터**는 잉글랜드 관련 이동 위주입니다 (적용 269건, 구단명 매칭 실패 등으로 미적용 약 56건).
- 4부 이하 리그에 속한 2군(예: 바이에른 II, 도르트문트 II)은 아직 팀으로 만들지 않았습니다.
- 유스·2군·실제 임대는 **새 세계**를 만들어야 반영됩니다.
- AI 구단은 감독·전술 개념이 없습니다. 경기 결과는 전력으로 먼저 정하고 명단·이벤트를 붙이므로, 징계·로테이션은 결과에 전력 보정으로만 반영됩니다.
- 엔진 나이는 시즌 단위로 오르고, 화면에 보이는 나이만 생일 기준입니다.
- 구단 레전드의 게임 이전 기록은 주요 구단 현역 장기 근속 선수만 근사치로 넣었습니다. 나머지는 게임 시작(2026/27) 이후 기록으로만 판정합니다.
- 세계 구단 랭킹의 역사·팬 시작값은 약 230개 구단만 근사 자료가 있고, 나머지는 리그 수준·구단 규모로 추정합니다. 리그 밖(배경) 구단은 경기 수가 적어 경기력이 거의 고정입니다.
- 히트맵은 터치 좌표를 기록하지 않는 경기 엔진 위에서 통계와 위치 모델로 재구성한 것입니다 (같은 경기 = 같은 히트맵).
- 감독 경질은 리그 경기 압박 기준이며 컵·대륙 대회 탈락은 직접 반영하지 않습니다. 대표팀 감독은 국제 대회가 끝날 때(기대 성적 대비)와 빅클럽 영입으로만 바뀝니다. 대표팀 실제 감독은 2026-09 기준 43개국이고 나머지는 처음 필요할 때 뽑습니다.
- 라이벌 관계는 `data_rivals.js`에 넣은 254쌍만 압니다 (목록 밖 지역 더비는 일반 구단으로 취급).
- 경기 탐색의 선수 조건은 출전 명단이 보관된 경기(1·2부 리그·컵·대륙·국제 대회)에서 정확하고, 명단이 없는 하부 리그는 득점·도움 경기만 잡힙니다. 예전 버전에서 지워진 시즌은 찾을 수 없습니다.
- **FC27+TFMKT**: 게임 이전 시즌은 대회 구분 없는 공식전 합계이고 평점·출전시간이 없습니다. 2025/26은 소속 구단만 있고 기록은 '-'입니다. Transfermarkt에 없는 선수(주로 유럽 밖 하부 리그, 약 5,500명)는 FC27 자료 그대로입니다.
- **FC27+TFMKT**: 2025/26~2026 여름 이동 날짜는 추정입니다 (겨울 이적 명단 114명 중 이동이 확인된 56명만 1월). 게임 이전 우승은 리그(구단 시즌 1위)와 2025/26 국내 컵·대륙 대회만이며, 그 이전 컵·대륙 대회 우승은 없습니다. 옛 시즌의 리그 이름은 Transfermarkt 표기(예: First Division)를 그대로 씁니다.
- **FC27+TFMKT**: 구단 대응 686개 중 낮음·없음 21개(주로 2군)는 게임 이전 기록이 이어지지 않습니다. 경기 기록은 1990년대 이전이 드물어, 오래된 레전드는 기록이 일부만 있습니다.
- 유스 명단은 UEFA 유스리그 참가 구단(맨유·아스널·첼시·맨시티·리버풀·레알·바르사·바이에른) 위주입니다. 다른 구단은 FC27에 있는 선수만 있습니다.
